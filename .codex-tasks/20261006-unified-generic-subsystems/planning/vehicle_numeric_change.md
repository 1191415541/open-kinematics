# 整车接触 frame 修正的数值验收调整建议

状态：用户于2026-10-07批准本修订。批准范围是默认非自转contact frame以及三个严格不匹配工况的独立登记。新机器门、完整数值门和复审通过；21项相关测试、快速集1624项及kernel/contracts158项通过；未据此切换或删除旧生产链。

## 已验证事实

- 八种整车输入已经由普通文档、统一 resolver、统一 compiler 和 ResultEnvelope 运行。
- 局部硬点在原声明单位中计算后转 SI，消除了世界坐标相减造成的浮点差异。
- 显式恢复原刚体与关节数据顺序后，五个无激励工况的状态逐位相同。
- 转向、非默认路面和初态、衬套曲线三个工况仍因轮胎 contact frame 从随 spin 转动的 hub 改为 upright 而改变结果。
- 诊断中仅恢复历史 frame_body/frame_center_local，八种工况的状态、反力、轮胎、力元、能量和诊断原冻结哈希全部相同。没有修改原基线，也没有放宽容差。
- 已保存实际运行证据：`raw/vehicle-document-evidence-probe.py` 和 `.json`；原实体顺序保存在 `tests/data/vehicle_dynamics_baseline/entity_layout.json`。

## 需要调整的验收语义

原 `case_parity_check.py` 要求八种当前整车结果均与旧快照逐位相同，与已要求修正的接触 frame 物理有冲突。将当前图恢复成旧 frame 会重新引入已修正的行为，不能作为生产方案。

建议分别记录旧严格数值结果和当前物理验收：

1. 旧严格数值结果：保留八种原冻结文件和断言。按稳定实体 ID 对齐顺序后，五个等价工况仍须通过原哈希；三个改变物理的工况保留原哈希不匹配事实，不把它们报告为严格 PASS。
2. 当前物理：对转向、非默认路面和初态、衬套曲线三个工况单独记录 `PHYSICAL_DIFFERENCE`，列出实际输入、模型实体差异、结果通道和量纲误差；实际提交须通过非自转 contact frame、Spin Boundary 和力矩平衡测试。其它模型实体、轮胎系数与输入表须保持一致；非预期差异仍阻断。
3. 发布门仅在用户批准这一默认物理修正后，才可将明确登记的三个差异作为已批准的物理变更处理；全部消费者、五个等价工况及其它数值、性能和结构门仍须通过。

不再承诺用历史参照文档重现全部八项。当前 Spin 校验拒绝轮胎 contact frame 继承声明轴承的相对自转；恢复旧 frame 的诊断图不满足这项约束。删除 Spin Port 以逃过校验、修改 resolver 后的物理 IR 或保留旧求解器作为验收生产者都不允许。历史诊断只说明差异来源，不作为新生产门的通过证据。

原基线文件不重录、不替换，三个严格不匹配状态与当前物理验收必须分别报告，禁止称“八种当前图逐位通过”。

## 实施边界

- 数值生产者只使用普通文档及唯一 resolver/compiler/native/envelope；实体顺序对齐只影响证据排列，不能借此修改物理模型或绕过作者层验证。
- 当前普通模型必须保持合法的非自转 carrier；不能增加公开兼容开关或替代生产路线。
- 原 preparation 和 decoder 只读诊断脚本不进入生产门；对应消费者完成迁移后退役。诊断数据作为原始证据保留。
- 允许登记的工况只有`steering`、`nondefault road and initial state`、`bushing force curves`；物理字段只有四个轮胎的`parameters.frame_body`与派生的`parameters.frame_center_local`，且新值必须对应声明轴承的非自转carrier。质量、惯量、其它力元、轮胎系数、初态、时间与激励表的其它差异均阻断。
- 当前诊断仅提供状态分量最大差异，尚不能作为机器发布判定。实施时必须导出三项完整通道差异、单位和输入指纹，逐项给出物理预期及独立验收界限；不能只按本次观测最大值放宽门槛。缺少这些证据或任一项未通过时，任务9步骤2仍失败。
- 本建议请求批准的是已明确要求的非自转contact frame作为默认物理以及三项严格不匹配的登记方式，不是提前批准发布、删除或尚未实现的数值门。
- `planning/interfaces.md:40-42` 和删除前退出门要明确上述验收语义，重新由只读子代理审查内部一致性。
- 已获批准，按上述边界实施机器验收并继续迁移消费者；验收和删除前退出门未通过前，任务9保持IN_PROGRESS。

## 机器验收实现

- 唯一生产者仍为普通文档 -> resolver -> `compile_resolved` -> native -> `ResultEnvelope`。只按原稳定ID排列完整实体行，不恢复历史接触frame或删除Spin声明。
- 原始参考数组一次性采集后逐通道验证八项原冻结哈希；机器门再次验证NPZ内容与原哈希、文件清单、完整实体映射。旧生产者只在raw的采集脚本中出现，不进入机器门。
- 所有模型参数、原始声明指纹、初态、求解器、时间与输入表逐项比较，允许差异仅为四胎carrier引用及局部中心。独立Spin检查按声明轴承检查非自转carrier、四个free边界及初始轮心一致性。
- 三项物理验收检查采样诊断的position/velocity/dynamics残差不超过原声明门限；按刚体质量、附加轮胎质量、惯量及实际姿态复算动能；检查机械能=动能+势能；从carrier位姿和速度复算平面接触压缩量及线性brush垂向力；检查全部约束两端合力和绕世界原点力矩平衡。
- 派生等式界限只取float64机器精度乘以公式运算规模及项的绝对值；动能为`256 * body_count * eps * max(1, sum(abs(energy_terms)))`，接触及机械能为`1024 * eps * max(1, sum(abs(terms)))`，合力/力矩分别为`512/1024 * eps * max(1, wrench_terms)`，四元数范数为`256 * eps`。这些是同次结果的等式误差界，不能解释为旧新轨迹差异的上界。
- 完整输入和结果写入`artifacts/vehicle-physical-evidence/`，报告每个稳定实体、通道列、单位、最大绝对差与RMS差；同时保留全部当前数组、提交JSON/二进制和哈希。报告明确区分5项`STRICT`与3项`PHYSICAL_DIFFERENCE`，后者原哈希仍不匹配。
- 补充轮胎brush投影、切向力、滑移速度、正常与brush储能；转向坐标/速度/目标/反馈力；衬套几何/变形/本构/储能；势能组成及区间功/耗散/残差账。约束ID集合必须与原布局相等，缺少反力记录不能空循环通过。衬套曲线子公式复用现有Python基元，仅作为native输出的跨实现核对，不宣称第三套独立本构引擎。
- 增补缺失反力及篡改切向力/转向力反例；真实native测试覆盖镜像和非零安装姿态下的多周spin，以及carrier转向时contact frame跟随carrier且不继承spin。
