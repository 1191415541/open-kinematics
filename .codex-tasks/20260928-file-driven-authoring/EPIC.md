# 文件驱动建模 Epic

## Goal

完整执行已批准快照 `.pi/plan/文件驱动的模板-子系统-总成与试验台体系-20260928-1451.md`，该文件是需求与实施范围的真源，不以本记录缩减范围。

1. 专家定义声明式模板拓扑及对外端口，支持刚体、硬点、运动副和力元。
2. 子系统引用模板，只修改声明的硬点数值、实例参数和属性文件绑定；不得修改拓扑或回写模板。
3. 弹簧、减振器、缓冲块通过版本化属性文件定义线性/非线性/分段本构，编译至现有内核。
4. 总成组合多个子系统，区分功能角色与位置角色，执行数量/位置/接口规则；局部覆盖不回写子系统。
5. Rig 文件描述实际支承、加载、驱动、测量，通过现有端口连接形成 SimulationAssembly。
6. 项目引用加载、诊断、专家模式 API、内容哈希和结果 provenance 完整贯通。
7. 内置模型与旧 Python 入口通过兼容转换走通用路径，保持冻结数值不变。

## Non-Goals

不引入依赖、新求解器、新 ABI，不修改冻结基线；不实施 GUI。专家模式是应用 API 的编辑模式，无法限制用户在外部编辑器中直接改写自己的文件。

## Done-When

所有子任务验收通过，且独立端到端测试从真实模板/属性/子系统/总成/Rig 文件完成 K/C 或动态求解；参数和属性曲线变化到达内核并改变预期响应，拓扑不变；前后位置、缺少实例、端口不兼容和越权拓扑修改均被拒绝；源文件不被覆盖；结果保留全部输入哈希。执行 check-fast、数值门、架构目录和全量回归，skip/xfail 不增长，git diff --check 通过。

## 原始需求原文

> 我想象的是要让当前项目实现类似adams car的用户定义方式：1.模板只供专家定义（需要在专家模式下创建或修改模板），模板里定义刚体、硬点、运动副、衬套、弹簧、缓冲块、减振器等等 2.模板定义好后，选择指定模板定义子系统，子系统有自己的role，role定义any、front、rear等等，role注意是定义子系统在总成的哪个位置，比如是前悬还是后悬 3.子系统创建好后，选择多个子系统、实验台创建总成，在创建总成时需要定义子系统是悬架还是转向等等 4.悬架总成、整车总成需要的子系统数量不一样，需要区分 4.模板、子系统、总成都已文件形式保存在电脑上，用户直接修改文件来定义。基于当前项目实现，要完全达到我的设想还需要做什么

> 我还需要补充一下：1.创建子系统后，可以修改硬点坐标和属性，但是不能创建和修改运动副、添加刚体等操作，相当于只能修改数值，不能修改拓扑，修改子系统数值不会改变模板 2.装配成总成后依然可以通过修改其中子系统的硬点坐标和属性

> 这里还有一个点：弹簧、减振器、缓冲块的属性不应该只通过数值定义，这三类弹性元件的属性应该直接引用属性文件，属性文件可以有不同定义，比如线性、非线性等等
