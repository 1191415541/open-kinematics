本文件回答 SPEC Done-When 第 3 条（对应父 Epic 判据 Done-When (c) 与事实 F7）：
**含数值微分步长与截断误差量级、双叉臂上与今日 `_instant_center` 的并列对照表、逐条差异来源解释。**

全部数字由 `raw/probe_numerics.py` 与 `raw/check_tilt.py` 实跑得到（退出码均 `0`，见 `raw/run_log.md`），
本文件只做转述与解释，不引入任何未实测的数字。

## 0. 口径先说清

引擎 **默认**返回的是**最小欧氏范数**那一支运动（`solve_rigid_motion` 的 docstring）。
今日 `_instant_center` 在正视图上求两臂线交点，**按定义是绕 `x` 轴的转动**。
所以对照必须读「角速度平行于 `x`」的那一支，否则比的是两件事。

引擎把这一族运动完整暴露为 `RigidMotion.null_space`。设最小范数支的立轴角速度为 `b`，
自由方向对它的灵敏度为矩阵 `M`（把自由系数映到立轴角速度），可达角速度集就是 `{b + M c}`。
「最接近绕 x 转动」被写成**尺度无关**的形式：

```
min over (c, λ):   | M c + b - λ e_x |
```

未知量同时含自由系数 `c` 和绕 x 的角速度 λ，所以不会靠放大 `c` 来把残差压小。
报告的 `fraction = 残差 / |λ|`：**0 表示该支确实是绕 x 的纯转动，量级 1 表示它不是**。
这个 `fraction` 一并打进对照表，因为几何 B 上它就是差异的主因。

## 1. 步长与截断/舍入误差量级

`raw/probe_numerics.py` 第 1 节实测（在装配好的双叉臂上，全套 16 条约束 / 65 行残差 / 72 列）：

```
h=0.0001: |J(h)-J(1e-5)|_inf=2.312e-06  |J|_inf=1.400e+03 sv_max=3.669611e+03 sv_min=1.901978e-04 rank=65
h=1e-05: |J(h)-J(1e-5)|_inf=0.000e+00  |J|_inf=1.400e+03 sv_max=3.669611e+03 sv_min=1.901978e-04 rank=65
h=1e-06: |J(h)-J(1e-5)|_inf=1.137e-07  |J|_inf=1.400e+03 sv_max=3.669611e+03 sv_min=1.901978e-04 rank=65
h=1e-07: |J(h)-J(1e-5)|_inf=1.023e-06  |J|_inf=1.400e+03 sv_max=3.669611e+03 sv_min=1.901979e-04 rank=65
h=1e-08: |J(h)-J(1e-5)|_inf=1.112e-05  |J|_inf=1.400e+03 sv_max=3.669611e+03 sv_min=1.901976e-04 rank=65
roundoff scale   eps*|f|/h = 2.220e-16 * 1e3 / 1e-6 = 2.220e-07 mm
truncation scale h^2*f'''/6 = (1e-6)^2 / 6            = 1.667e-13
```

读法：

- 选定的步长是 `NUMERICAL_STEP = 1e-6`（与内核 `kernel_model_constraint.cpp:280` 的 `constexpr double h = 1e-6` 一致）。
- **实测误差在这条扫描上于 `h = 1e-6` 取最小**（`1.137e-07`）。往小走（`1e-7`、`1e-8`）误差按 `1/h` 上升：`1.023e-06`、`1.112e-05`，
  即每缩小 10 倍步长，误差放大 10 倍 —— 这是**舍入**项 `eps·|f|/h` 的特征。往大走（`1e-4`）误差为 `2.312e-06` —— 这是**截断**项。
- 量级对得上：舍入项 `eps·|f|/h ≈ 2.2e-07`（`|f|` 取 1e3，即被相减的坐标尺度，实测最大点坐标 1550 mm），
  截断项 `h²f'''/6 ≈ 1.7e-13`。舍入项比截断项大 6 个数量级，所以**步长已经是舍入主导，不能再小**。
- 注意 `|f|` 不是装配残差（装配处残差恒为 0，实测 `max|f| = 0.0`），而是残差**被构筑时用到的坐标尺度**。
  取错这一项就会得到「`~2e-10`」这种与实测差三个数量级的估计 —— 引擎模块 docstring 原先正是这样写的，本行已按实测改正。
- `sv_max = 3.6696e3`、`sv_min = 1.902e-04`、`rank = 65` 在整条扫描上不变：步长没有改变装配的秩。
  `RANK_TOLERANCE = 1e-9` 相对 `sv_max` 的截断阈值是 `3.7e-6`，落在 `sv_min`（`1.9e-04`）之下 2 个数量级，所以秩判定对步长不敏感。

### 3.3 差异来源，逐条

**（1）`(a)` 与 `(b)` 的差 = 今日把「两内侧硬点取平均」当成了臂的转轴。**

`roll_centers._instant_center`（`roll_centers.py:93-99`）用
`upper_inner = (UPPER_INBOARD_FRONT + UPPER_INBOARD_REAR)/2` 建臂线。装配体的上臂实际只铰在
`uca_mount_L_inner_front`（`(1400,-500,500)`）一根转轴上；`inner_rear` 是**没有铰链的硬点**（实测 16 条约束里没有任何一条引用它）。

- A、C：两个内侧硬点的 y、z 相同（只差 x=150），平均值在 yz 平面上**就是**前点，所以 `(b)-(a) = 0.0`。
  这解释了为什么这个 bug 在出厂几何上完全不可见。
- B：只有 UPPER_INBOARD_REAR 的 z 从 500 变成 520，x/y 都没动，所以工程式里的平均值只在 z 上偏 10。
  正视图只看 [y,z]：今日的上臂线过 (-500, 510) 与 (-750, 350)，斜率 dy/dz = 1.5625；
  真转轴的上臂线过 (-500, 500) 与 (-750, 350)，斜率 1.6667。下臂线未动（z = 100 的水平线），
  交点就在 z = 100 上：-500 + 1.5625*(100-510) = -1140.625 对 -500 + 1.6667*(100-500) = -1166.667，
  差恰好 26.0417 —— 与实测 (b)-(a) = -26.0417 逐位一致。这条差异的全部来源就是那个平均化，没有别的项。
  该硬点的 x = 150 偏移对正视图无影响（正视图不读 x）。
- 这一条与 SPEC 的 F7 一致：差异是今日的平均化近似造成的，不是引擎的。
  并且它把该近似的作用范围钉死了 —— 只在两内侧硬点的 yz 相同时才无害。

**（2）`(b)` 与 `(c1)` 的差 = 数值微分的步长误差，量级 `3e-6` mm。**

A：`-3.060e-06`；C：`-3.066e-06`；B：`-2.674e-06`。
三者同量级、符号一致，且与第 2 节平面四连杆的 `1.3e-5` / `2.8e-5` 同源（都是 `h=1e-6` 的舍入项经螺距分母放大）。
**这一条不解释成建模差异**：它随步长变化，不随几何意义变化。

**（3）`(c1)` 与 `(c2)` 的差 = 全轴的那族额外自由（含转向拉杆、对侧、齿条）。**

A：`-3.06e-06`（与 c1 一致到 `1e-10` 内）；C：也一致到 `1e-10` 内；B：`+0.1215`。
B 上这个 `0.12` mm 的差不是噪声，是**真实的机构学差别**：全轴的自由族比左四杆多，
而 B 的转轴已不平行于 x，多出来的自由度让「角速度严格平行于 x」这个条件**只能近似满足** ——
见表里最后一列：B 的 `(c1)` 非绕 x 成分是 `1.111e-01`，`(c2)` 是 `2.2e-05`。
换言之，B 的 `(c2)` 支被选成「最接近绕 x」，残差就是那 `0.12` mm 的位置偏移。

**（4）`(c2)` 的非绕 x 成分把「几何 B 没有精确解」量化了。**

- A、C：`1.1e-16` / `1.5e-14` —— 精确，因为两臂转轴都平行于 x，机构确实允许绕 x 的纯转动。
- B：`2.2e-05`（全轴）/ `1.111e-01`（左四杆）。**左四杆上没有精确解**：把上臂转轴转斜 3.81° 后，
  绕 x 的纯转动不再是该四杆的运动（实测该族到 x 轴直线的最小距离是 `1.111e-01`）。
  这就是为什么 B 的 `(c1)` 与 `(b)` 的差（`-2.674e-06`）虽然仍很小，但那一支的角速度已经是 `[1.0, -0.111, 0.0]`：
  对照值仍可用，但必须同时报出它偏离「纯绕 x」多远。

**（5）`(d)` 最小范数支为什么不能拿去对照。**

A：`+3.458` mm；B：`+3.305` mm；C：`+0.883` mm。
最小范数支是在 72 维切空间里范数最小的那个，它把运动摊到了转向拉杆、对侧等所有自由方向上，
**没有理由与正视图的绕 x 构造相等**。A 上它偏离 `3.458` mm（`6.7e-11` 那支偏离 `3e-6`），
差了六个数量级 —— 若拿它当对照值，结论会是「引擎与今日差 3.5 mm」，而那纯粹是选错了支。
这一点是本次对照最重要的操作约定，已写进 `raw/engine_contract.md`。

**（6）镜像侧 `(e)`。**

同一口径读 `upright_R`，A/C 与左侧数值精确对称（`±y` 反号），B 也对称，
非绕 x 成分相同 —— 构造对左右一致，没有把某一侧的专门逻辑写进引擎。

### 3.4 把转轴越转越斜，差异怎么走

`raw/check_tilt.py` 把 B 的后点继续抬高，用**与第 3.2 节相同的对照支口径**测量：

```
 z of UPPER_INBOARD_REAR  tilt(deg)    fraction  |engine-pivot|  |engine-today|
                   500.0      0.000   1.119e-16       3.069e-06       3.069e-06
                   520.0      3.814   2.223e-05       1.224e-01       2.592e+01
                   560.0     11.310   7.348e-05       1.469e+00       6.815e+01
                   650.0     26.565   1.248e-04       4.737e-01       1.386e+02
                   800.0     45.000   3.792e-04       1.200e+00       2.093e+02
```

读法：

- `tilt` 是**上臂真转轴**与 x 的夹角（读 `uca_mount_L_inner_front.axis_a`），不是拟合出来的。
  `z=500` 即出厂几何，倾角 `0.000°` —— 对照表 3.2 里 A/C 的「精确」就是它。
- `z=520` 一行 `|engine-pivot| = 1.224e-01`、`|engine-today| = 2.592e+01`，与第 3.2 节 B 行的
  `+0.1215` / `-25.9202` 一致（符号与基准点不同），说明两个脚本同口径。
- **`|engine-today|` 随倾角单调放大**（`3.1e-06 → 2.1e+02`），而 `|engine-pivot|` 停在 `~1 mm` 以下。
  即：一旦把今日公式里那个错误的内侧锚点换成真转轴，剩下的分歧就与倾角无关了。
  这把第 3.3(1) 条的归因钉死：分歧的主体是今日的平均化锚点，不是引擎。
- `fraction`（非绕 x 成分）随倾角从 `1.1e-16` 升到 `3.8e-04`：转轴越斜，机构离「绕 x 的纯转动」越远。
  它比 3.2 节 B 行左四杆的 `1.111e-01` 小三个数量级，因为**全轴**的自由族比左四杆大得多，能把角速度拉得更靠近 x。
- `z=650` 那一行 `|engine-pivot|` 比 `z=560` 小（`4.737e-01 < 1.469e+00`）：这不是噪声，
  是该口径下真轴交点本身的非单调性（转轴倾斜后两条臂线在 yz 上的交点位置并不单调移动）。
  本行的结论只依赖 `|engine-today|` 的单调放大，不依赖这一列。

## 4. 自由族与驱动无关性

`raw/probe_numerics.py` 第 4 节实测：

```
stacked rank=66 nullity=6 (free members)
axis-point spread over +-1e-3 along every free direction (mm): [9.6598122e-05, 4.6909477e-05, 0.000865505927]
drive the wheel centre vertically   : |omega|=2.4100218423e-03 axis point=[1418.144566943, -1163.208537807, 101.659902887] sign-normalised direction=[0.995841596388, -5.98e-10, 0.091101673438] pitch=3.7801189521e+01
drive the rack laterally            : |omega|=6.6945050980e-03 axis point=[1418.144567504, -1163.208537689, 101.659902938] sign-normalised direction=[0.995841596258, 8e-11, 0.091101674857] pitch=3.7801190059e+01
drive the upright's local x-rotation: |omega|=1.0041757683e+00 axis point=[1418.144567531, -1163.20853769, 101.659902939] sign-normalised direction=[0.995841596256, 1.36e-10, 0.091101674878] pitch=3.7801190041e+01
```

读法：

- 65 行约束 + 1 行驱动堆叠后 `rank = 66`，72 维切空间里还剩 `nullity = 6`。
  **引擎如实报出这 6 个自由方向**（`RigidMotion.null_space`），不假装解唯一。
- 沿每个自由方向走 `±1e-3`，轴上点最多移动 `8.66e-04` mm（三个分量 `9.7e-05`、`4.7e-05`、`8.7e-04`）。
  即**自由族对轴上点的影响低于 `1e-3` mm** —— 这就是第 3.2 节里 `(c1)` 与 `(c2)` 在 A/C 上能一致到 `1e-10`、
  而在 B 上不能的原因：B 的差异不是自由族噪声，是 3.3(3) 说的真实机构差别。
- 三种完全不同的驱动（轮心竖直、齿条横向、立轴局部 x 转动）读出**同一根轴**：
  轴上点一致到 `~1e-6` mm，方向一致到 `~1.5e-10`，螺距一致到 `~1.4e-6`（都是 `3.7801190e+01`）。
  角速度幅值差三个数量级（`2.4e-3` / `6.7e-3` / `1.0`）而轴不变 —— 轴只取决于机构，不取决于用哪个驱动去激发它。
