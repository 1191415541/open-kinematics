# P3 步骤 4 证据：显式中心序列时间差分

> SPEC §47（步骤 4）：实现显式中心序列时间差分；模板/端点/误差元数据齐全，
> **不跨事件/无效点**。落点：`sampled_time_difference` 专项测试。
> 本步**不修改 native/C++**，纯 Python 读取层。

## 0. 结论

交付 `results/differences.py`（`sampled_time_difference` / `SampledDifference` /
`DIFFERENCE_TEMPLATES` / `as_measurement`）与
`tests/characteristics/test_sampled_time_difference.py`（**34 用例**）。

**本模块存在的理由不是算术，而是沉默。** 差商有时是唯一可得的答案（求解器没有存速率），
危险在于它会**安静地**假定四件事，而这四件事常常为假：

1. 序列按时间严格递增（重复或逆序的时间戳使除数成零或为负）；
2. 相邻样本位于运动的**同一分支**（事件或活动模式切换夹在中间时，差商是跨不连续的
   平均，两侧都不是导数）；
3. 邻居**可用**（从被契约标为不可用的样本上取值，等于伪造数据）；
4. 结果是**导数**（中心差商是二阶精度，不是精确，且误差量级需要三阶信息）。

四项**全部拒绝**而不是返回一个看似合理的数，并把做过的事**记下来**：每个样本用了哪个
模板、哪些端点是单侧的、真实时间跨度、以及曲率尺度。

**不声称解析**：解析路径是步骤 3 的 `trajectory.geometry_rate_request`，两者刻意分开，
调用方无从混淆。

## 1. 四个模板与边界语义

| 模板 | 含义 |
|---|---|
| `central` | 两侧邻居都可用且同块 |
| `forward_one_sided` / `backward_one_sided` | 只有一侧可用（端点、块边界、无效邻居） |
| `undifferenced` | 无可用邻居——**报告**，不猜 |

`blocks` 给出"运动在此处不可微"的样本下标（事件、活动模式切换或任何声明的间断），
**没有任何模板跨过块边界**。`block_id = cumsum(block_start) - 1` 使边界 `k` 真正落在
`k-1` 与 `k` 之间。样本 0 无条件自成一块（它前面没有东西）。

## 2. 非均匀网格的加权

朴素商 `(v[+1] − v[−1]) / (t[+1] − t[−1])` 在非均匀网格上把两侧不同的单侧斜率**按错误的
权重**平均。使用的二阶形式按**另一侧**的步长加权：

```
f' ≈ [ h₋² (f₊ − f) + h₊² (f − f₋) ] / [ h₊ h₋ (h₊ + h₋) ]
```

均匀网格上退化为熟悉的中心商。

**★ 关于它的诚实说明（复审纠正了我原来的过度声称）**：我原先在测试名与注释里写
"加权换来二阶精度"。**实测不成立**：在光滑非均匀网格（`t = linspace^1.5`、
`f = sin 3t`）上，朴素商在**每一档**分辨率都**略优**于我用的加权式：

| n | 加权式误差 | 朴素商误差 | 加权更好？ |
|---|---|---|---|
| 21 | 2.242e-02 | 1.937e-02 | 否 |
| 41 | 5.969e-03 | 5.435e-03 | 否 |
| 81 | 1.532e-03 | 1.427e-03 | 否 |

两者都是二阶。选用加权式的理由是**它对二次式精确、且均匀网格上退化为中心商**，
**不是**因为它优于朴素形式。测试名与注释已改为如实陈述，并把实测结论写进 docstring。

## 3. 曲率尺度（原 `error_scale`）——一个我先后改对两次的字段

第一版用三阶差分估 `f'''`，但三维模板**看不到** `f'''`（需要第四个点）——它量到的是
`f''·h²`。第二版改成 `0.5·|fwd_slope − bwd_slope|·span/2`。

**复审的锐利之处**：它指出该量恒等于 `span²·f''/8`（均匀网格上即 `h²·f''/2`），
而 `f = t³` 的真实截断误差是 `h²/6·f''' = h²`——**与 `f''` 无关、是常数**。

**我独立复现确认**：真实误差在全部 19 个内点恒为 `0.002500`；曲率尺度比值
`last/first = 19.0`。所以该量**既不是误差的量级、也不是误差的界**。

**修正**：字段**改名为 `curvature_scale`**，docstring 明确写出"它**不是**误差估计"及其原因
（三维模板无法观测决定截断误差的三阶导数），并把"在 `f=t³` 上真实误差恒定而任何基于
曲率的量随 `t` 增长"这一实测事实写进去。需要截断误差界的调用方**只能靠加密网格比较**。
测试相应改为断言它跟踪**曲率**（在 `f=t³` 上随 `t` 线性增长、随网格加密而下降），
而不是断言它跟踪误差。

**教训**：把字段命名为 `error_scale` 本身就是一次**过度声称**——名字比代码做了更多承诺。

## 4. `time_step` 的含义（复审发现的文档失真）

docstring 原写"the actual real-time divisor used"。但 central 分支记录的是 `span = h₊ + h₋`，
而实际除数是 `h₊·h₋·(h₊ + h₋)`——`span` 只是其中一个因子。

**后果**：调用方按 docstring 反推（`Δvalue / time_step`）在 central 样本上得不到自洽结果，
而在单侧样本上却成立——**同一字段在两类样本上语义不同，docstring 只描述了一类**。
这是"声称的性质代码没有实现"，会让审计代码写出静默错误的检查。

**修正**：docstring 改为"模板**跨越的跨度**"，并明确说明 central 样本的商不除以它。
测试相应新增断言钉住两类语义的差别。

## 5. 独立复审（D2）：1 个真缺陷、4 个测试缺口、1 处文档失真

复审确认了**正确的部分**：`block_id` 边界语义正确；样本 0 自成一块；连续边界正确地
使中间样本 `undifferenced`；`usable = valid & isfinite` 两个方向都正确；加权公式
**代数正确**；状态/原因配对在**全部 `continue` 分支**上成立；`MIN_STEP_S` 守卫**处处到位
且可达**（严格递增但 `0 < step ≤ 1e-12` 的轴确实命中守卫）；重复/乱序 `blocks` 安全。

### 复审主张中我**独立验证为正确**的

- **曲率尺度语义**（§3）——复现，已修。
- **`time_step` 文档失真**（§4）——复现，已修。
- **浮点 `valid` 掩码被真值性强转**：实测 `np.full(6, 0.5)` 被解释为"**全部有效**"。
  传入 0/1 权重数组的调用方会得到**有效性判定的静默反转**，而契约其他地方
  （`MeasurementValue`、`statuses_for`）都以抛错拒绝非法输入。**已修为断言 `dtype == bool`**。
- **相邻边界与末索引边界无覆盖**：实测行为**正确**（`blocks=[2,3]` → 样本 2 为
  `undifferenced`；`blocks=[5]` → 末样本 `undifferenced`），但**完全未被测试**。已补两条。
- **非均匀测试名不符实**：它声称二阶收敛，实际只断言一个二次式上的精确性；且其中的
  "非空洞性"检查 `naive = (times[2]-times[0])/(times[2]-times[0])` 恒为 1.0 后 `del`——
  **纯空操作，且算的根本不是朴素商**。已修正断言与命名（§2）。

### 复审主张中我**独立验证为错误**的（记录之，防其被当成事实沿用）

复审声称"**把权重写反（`before_step`/`after_step` 对调）的实现仍会通过**
`test_a_non_uniform_grid_keeps_second_order_accuracy`，而那个实现在非均匀网格上是真错的"。

**我用破坏验证直接反驳**：植入权重对调变异，**CAUGHT**
（`test_a_non_uniform_grid_reproduces_a_quadratic_exactly` 失败）。
原因：该测试断言的是**值**的精确性，而权重对调会改变值；复审把"测试没有检验二阶**收敛阶**"
误推为"测试看不见权重错误"。**结论：复审这一条不成立**，我未据此改动代码。

### 第一轮 7/8，MISSED 的那一项是**测试的缺陷**

第一轮漏掉的是"有效性掩码被忽略、只看有限性"：我的**全部**无效样本都携带 NaN，
于是 `valid` 掩码与"是否有限"**在整个测试套件里完全等价**——掩码从未被真正检验。
修法是加入一个**有限值但 `valid=False`** 的哨兵（999.0）用例，使两者可分。

这与 P3 步骤 2/3 是**同一模式的第三次出现**：**夹具若比真实情形"整齐"，缺陷就住在
夹具与真实之间的缝里**（步骤 2 是"除第 1 列全 0"，步骤 3 是"轴长恒为 1"，
本步是"无效样本必然是 NaN"）。

修完哨兵用例后我的第一版"非空洞性"检查又写错了：我断言中心商 `(v[3]−v[1])/(t[3]−t[1])`
会泄漏哨兵，实测差值 0.0——因为**中心商跳过样本 2**。真正的泄漏路径是其两个邻居的
**单侧**模板。已改为对单侧路径断言。

## 8. 缺口与不声称

- **本步与真实动态运行未接线**：`sampled_time_difference` 只吃 `times` + `values`，
  测试只用手工构造序列。真实运行的事件时间来自 `ResultEnvelope.contact_events`
  （`ContactEvent(time_s, element_id, transition)`，`envelope.py:47`），
  **从事件时间映射到样本下标这一步尚未实现**——调用方目前必须自己给出 `blocks`。
  这是 R9"生产消费方"缺口的同一处（`trajectory.py` 亦无生产消费方）。
- **活动模式切换的边界未接入**：`blocks` 是通用机制，但"哪些样本是模式切换点"
  目前没有任何生产者。事件可来自 `contact_events`，模式切换尚无对应通道。
- **误差量级不可得**：三维模板看不到 `f'''`，故本模块**只给曲率尺度**。
  需要截断误差界必须加密网格比较，这一点已写进 docstring 与 §3。
- **不可微点**：`blocks` 让调用方**声明**不可微点，但**探测**不可微点（例如靠
  二阶差分突增自动识别）未实现，属 SPEC §64 的"不可微点"范围。
- **本模块不处理伪时间**：SPEC §39 的准静态伪时间拒绝属采样选择层。
- `curvature_scale` 跨网格不可比（它含 `span²`），若将来需要跨网格比较须先归一化。
  已在 §3 记录，当前无调用方。
