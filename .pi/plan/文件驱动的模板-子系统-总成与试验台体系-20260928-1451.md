## 目标

把当前 Python 代码驱动的可组合多体模型扩展为文件驱动的 Adams/Car 式用户定义体系：专家通过模板文件定义拓扑；普通用户通过子系统文件修改硬点和属性文件引用；总成文件组合多个子系统并允许装配级数值覆盖；试验台文件与总成连接；求解链读取最终有效模型。模板拓扑在子系统和总成层不可修改。

## 领域模型冻结

拆分现有含义冲突的 `role`：

- `functional_role`：`suspension`、`steering`、`wheel`、`chassis`、`brake`、`drive`。
- `placement_role`：`any`、`front`、`rear`，后续可扩展到 `front_left`、`front_right` 等。

对象关系固定为：

```text
TemplateDefinition  -> 定义拓扑和可覆盖槽位
SubsystemDefinition -> 引用模板，填写硬点和属性文件
AssemblyDefinition  -> 引用多个子系统，分配功能/位置并提供装配级覆盖
RigDefinition       -> 定义试验台及其端口、加载和测量能力
SimulationAssembly  -> Assembly + Rig + 连接结果
```

允许的修改边界固定为：

- 模板：专家模式可修改刚体、运动副、元素、端口和属性槽位。
- 子系统：只能修改已声明硬点的坐标、属性值来源和实例参数；不能新增/删除/修改刚体、运动副或弹性元件拓扑。
- 总成：可以修改其中子系统的硬点坐标和属性文件绑定；修改保存为总成级 `overrides`，不回写模板或原始子系统文件。
- 弹簧、减振器、缓冲块的本构属性全部通过属性文件引用；允许线性、非线性、分段曲线等文件模型。

## 实施阶段

### 1. 建立文件契约和版本化 schema

新增或调整 `suspension_contracts` 中的版本化 JSON Schema：

- `template.schema.json`
- `element_properties.schema.json`
- `subsystem.schema.json`
- `assembly.schema.json`
- `rig.schema.json`

模板 schema 至少覆盖：

- `functional_role`
- `allowed_placement_roles`
- 刚体
- 硬点角色
- 运动副
- 弹簧、减振器、缓冲块、衬套、轮胎和其他力元
- 端口与端口需求
- 属性槽位及允许的 `element_type` / `model`
- 输出声明

元素属性 schema 至少覆盖：

- `element_type`: `spring`、`damper`、`bump_stop`
- `model`: `linear`、`nonlinear`、`piecewise` 等
- `units`
- `parameters` 或 `curve`
- 版本、名称和元数据

所有 schema 通过 `suspension_contracts.multibody` 的统一加载和校验入口验证；schema 校验错误必须包含文件路径、字段路径和原因。

### 2. 重构模板领域模型

主要修改：

- `packages/suspension_multibody/src/suspension_multibody/templates/model.py`
- `packages/suspension_multibody/src/suspension_multibody/templates/instantiate.py`
- `packages/suspension_multibody/src/suspension_multibody/templates/registry.py`
- `packages/suspension_multibody/src/suspension_multibody/templates/roles.py`

实施内容：

- 将 `Template.role` 迁移为 `functional_role`，保留兼容读取期的旧字段转换。
- 增加 `placement_roles` 或 `allowed_placement_roles`。
- 将弹簧、减振器、缓冲块等纳入统一 `ElementDefinition`，模板保存连接拓扑，不能保存具体本构数值。
- 将 `PropertySlot` 从数值槽位改为属性文件槽位，至少包含 `element_type`、允许的模型类型和是否必需。
- 保留模板 JSON round-trip，但改为新 schema 格式。
- 明确 builder 只作为专家扩展机制；普通文件模板必须能够完全通过声明式数据实例化，不依赖任意 Python builder。
- 增加模板拓扑指纹 `topology_hash`。

模板校验必须拒绝：重复实体、未知刚体引用、未知硬点引用、未知属性槽位、非法端口、运动副端点缺失、元素类型与属性槽位不匹配。

### 3. 实现属性文件和本构解析

主要修改：

- `packages/suspension_multibody/src/suspension_multibody/properties/load.py`
- `packages/suspension_multibody/src/suspension_multibody/properties/`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/element_build.py`
- 必要时调整 `packages/suspension_contracts/src/suspension_contracts/contracts/multibody_model.schema.json`

实施内容：

- 为弹簧、减振器、缓冲块增加强类型属性文档模型。
- 支持线性、非线性和曲线型本构文件。
- 增加属性文件引用对象，包含路径、类型、模型和内容 hash。
- 加载时校验 `element_type` 与模板元素一致。
- 校验单位、参数范围、曲线点顺序、有限数值和必要字段。
- 将现有 `dict[str, float]` 属性路径迁移为 `property_bindings -> resolved constitutive properties`。
- 求解模型编译时将解析后的本构数据转换为内核 contract 所需的 `parameters` / `blob`。
- 记录 `property_file_hash` 和 `effective_values_hash`，不把属性文件内容隐式写入模板。

### 4. 实现子系统文件和不可变拓扑实例

建议新增：

- `packages/suspension_multibody/src/suspension_multibody/authoring/documents.py`
- `packages/suspension_multibody/src/suspension_multibody/authoring/loader.py`
- `packages/suspension_multibody/src/suspension_multibody/authoring/resolve.py`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/instance.py`

实施内容：

- 新增 `SubsystemDefinition`，包含模板引用、功能角色、位置角色、硬点值和属性文件绑定。
- 子系统加载时先加载模板，再校验所有硬点和属性名称属于模板声明。
- 子系统只允许覆盖数值和属性文件引用。
- 对 `bodies`、`joints`、`elements`、`ports` 等拓扑字段出现修改时直接报错。
- 增加 `effective_subsystem`，返回“模板拓扑 + 子系统数值”的只读有效实例。
- 支持同一个模板实例化到 `front`、`rear` 或 `any` 位置。
- 统一输出子系统拓扑 hash、数值 hash 和属性引用 hash。

### 5. 实现总成文件、位置分配和数量规则

主要修改：

- `packages/suspension_multibody/src/suspension_multibody/connections/policy.py`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/types.py`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/entry.py`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/vehicle_assembly.py`
- `packages/suspension_multibody/src/suspension_multibody/subsystems/si_assembly.py`

实施内容：

- 新增 `AssemblyDefinition` 和装配级子系统引用。
- 总成引用子系统文件时明确指定或校验 `functional_role`、`placement_role`。
- 将当前 `axle` / `vehicle` 规则扩展为带数量、位置和端口约束的 Assembly Policy。
- 至少支持：
  - 单轴悬架总成：悬架必需一个，车身支承必需一个，转向可选，制动/驱动禁止，车轮由试验台提供。
  - 整车总成：前悬架一个、后悬架一个、车身一个，转向/制动/驱动按规则约束，四个轮端必须完整。
- 保留现有 `compose_axle()` / `compose_vehicle()` 作为兼容入口，但内部转入通用总成解析和组合路径。
- 禁止总成文件修改子系统拓扑；只允许写 `overrides.hardpoints` 和 `overrides.property_bindings`。
- 使用 copy-on-write 语义：总成级覆盖只保存于总成文件，不修改原始子系统文件。
- 解析完成后生成端口连接图，并在编译前拒绝重复角色、位置不匹配、缺少必需子系统和非法引用。

### 6. 实现 Rig 文件和 Simulation Assembly

主要修改或新增：

- `packages/suspension_multibody/src/suspension_multibody/rigs/`
- `packages/suspension_multibody/src/suspension_multibody/modeling/assembly.py`
- `packages/suspension_multibody/src/suspension_multibody/connections/`
- `packages/suspension_multibody/src/suspension_multibody/authoring/rig_loader.py`

实施内容：

- 新增 `RigDefinition` 文件格式。
- 声明试验台支持的总成类型、必需端口、可选端口、支承、加载器、驱动器和测量通道。
- 将现有端口匹配和自适应连接机制接入文件加载流程。
- 构建 `SimulationAssembly = Assembly + Rig + resolved connections`。
- 缺少必需端口、端口能力不匹配或试验台不支持该总成类型时，给出结构化错误。
- 保持 `Assembly` 与 `SimulationAssembly` 的边界，不把试验台规则写入模板或子系统。

### 7. 实现项目目录、引用解析和专家模式边界

新增或调整：

- `packages/suspension_multibody/src/suspension_multibody/authoring/project.py`
- `packages/suspension_multibody/src/suspension_multibody/authoring/security.py`
- 项目 README 和文件格式文档

实施内容：

- 支持从项目目录扫描和加载模板、属性、子系统、总成、Rig 文件。
- 支持相对路径解析、循环引用检测、文件存在性检查、schema 版本检查和内容 hash。
- 增加专家 API：创建/修改/发布模板。
- 增加普通用户 API：创建子系统、修改硬点、选择属性文件、创建总成覆盖。
- 普通用户接口不得接受拓扑字段。
- 专家模式不能只依赖 UI 隐藏按钮，核心 authoring API 也必须执行权限边界。
- 输出明确的加载诊断，不允许静默忽略未知字段或非法拓扑覆盖。

### 8. 迁移现有内置模型和兼容入口

实施内容：

- 将当前内置 double wishbone、steering、wheel、brake、drive 等模板转换为新模板文件或等价内置文档。
- 将当前测试 fixture 的硬点和参数迁移为子系统文件/属性文件 fixture。
- 为旧的 Python `Template`、`AssemblyRequest` 和现有 VehicleModel 提供兼容转换层。
- 保持已有 K/C 求解结果、动态 hash 和 Adams 对标结果不变。
- 不重录任何冻结基线；只有在明确证明数值未变化且得到授权时才允许更新基线。

## 验收标准

最终必须能完成以下端到端流程：

1. 专家创建一个模板文件，声明刚体、硬点、运动副、弹簧、减振器、缓冲块和属性槽位。
2. 普通用户引用模板创建前悬架子系统。
3. 用户修改子系统硬点坐标和属性文件引用，模板文件 hash 和拓扑 hash 不变。
4. 用户尝试新增刚体、修改运动副或添加元素时，加载失败并指出拓扑字段不可在子系统层修改。
5. 用户引用前悬架子系统和转向子系统创建悬架总成。
6. 用户在总成文件中覆盖子系统硬点和弹簧/减振器/缓冲块属性文件，原始子系统文件不变。
7. 用户使用前、后悬架子系统创建整车总成，前后位置和数量规则正确执行。
8. 用户将不兼容的子系统放入总成时，系统拒绝并报告功能角色、位置或端口原因。
9. 用户将总成绑定到 Rig 文件，形成 Simulation Assembly，并完成现有 K/C 或动态求解流程。
10. 修改线性属性文件为非线性属性文件时，拓扑 hash 不变、属性 hash 改变，求解器收到新的本构数据。
11. 所有模型和结果 provenance 都记录模板、子系统、总成、Rig 和属性文件 hash。

每个阶段增加针对性测试，最终按仓库约定执行：

```bash
uv run --no-sync ruff check .
uv run --no-sync ty check .
uv run --no-sync python packages/suspension_multibody/tests/architecture/legacy_surface_gate.py --check
uv run --no-sync python packages/suspension_kernel/scripts/check_module_layering.py --strict --final
uv run --no-sync python packages/suspension_multibody/scripts/check_composable_release.py --skip-isolation
uv run --no-sync pytest packages/suspension_multibody/tests \
  --ignore=packages/suspension_multibody/tests/adams \
  --ignore=packages/suspension_multibody/tests/architecture \
  --ignore=packages/suspension_multibody/tests/cases -q -p no:cacheprovider
uv run --no-sync pytest packages/suspension_kernel/tests packages/suspension_contracts/tests -q -p no:cacheprovider
```

由于该改动会触及求解模型装配、硬点解析和弹性元件本构路径，收尾时还必须执行：

```bash
just gate-numeric
```

如修改跨越完整车辆装配和多个子系统，提交前执行：

```bash
just test-all
```

## 非目标

- 本阶段不引入新的求解器或新的 C++ 内核 ABI。
- 不改变现有 K/C 物理语义和 Adams 对标定义。
- 不允许普通用户通过子系统或总成文件修改模板拓扑。
- 不把弹簧、减振器、缓冲块属性内联为普通数字字段作为长期方案。
- 不把 Assembly、Rig 和 Simulation Assembly 合并成一个对象。

## 交付顺序

依赖顺序为：

```text
文件 schema
  -> 模板拓扑模型
  -> 属性文件解析
  -> 子系统实例
  -> 总成规则与覆盖
  -> Rig 连接
  -> 项目加载和专家边界
  -> 内置模型迁移与端到端验收
```

每一阶段完成后先通过该阶段测试，再进入下一阶段；所有阶段合并后执行完整快速检查、数值门和必要的全量回归。
