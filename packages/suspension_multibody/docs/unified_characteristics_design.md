# 统一多体特性分析设计

状态：设计草案，已完成独立架构与物理审查及修订，未实施。日期：2026-10-09。

## 1. 结论与交付边界

建立统一的 `characteristics` 特性分析能力，覆盖悬架台架与整车、独立平衡态与动态轨迹。沿用 `ResolvedModel -> ResolvedSolvePlan -> compile_resolved -> run_compiled -> ResultEnvelope`；特性请求是求解计划的输出请求，不是新 Study、Case family、模型构建器或第二个仿真入口。

统一的是声明、响应数据、指标算法和结果查询；运动学摄动、静态平衡摄动、真实时间导数与动态载荷响应仍有各自明确的物理含义。SVC 作为用户熟悉的功能名称，内部使用 `Characteristic Analysis`，避免把动态特性误命名为静态柔度。

目标交付：

- 前束、外倾、轮心位置等测量的输入变化率与真实时间变化率。
- 轮端和指定 frame 的局部线性响应，包括左右、前后及车身耦合。
- 明确定义的几何侧倾中心、纵倾相关中心、空间瞬时轴；另行区分受载响应定义。
- 动态轨迹各指定采样点上的几何特性和连续动态小扰动能力。
- 收口已有滚心、螺旋运动和重复测量计算，使每种算法只有一个生产归属。

本设计不包含硬点优化、伴随梯度、二阶曲率、频响工具或新力律，不引入依赖。

## 3. 四类请求语义

| 请求域 | 回答的问题 | 准静态样本 | 动态样本 |
|---|---|---|---|
| `kinematic` | 在给定约束和响应边界下，单位驱动对应怎样的允许运动？ | 支持，要求驱动后可辨识 | 支持；是当前构型的虚拟运动，与实际速度分开 |
| `equilibrium` | 平衡态附近，单位载荷/运动输入产生怎样的静态响应？ | 支持，要求残量合格 | 非平衡样本不直接支持；另行配平得到新样本才能计算 |
| `trajectory` | 当前实际运动中，测量每秒怎样变化？ | 独立平衡网格没有真实时间导数 | 支持，用速度、角速度、内部状态导数及输入导数 |
| `dynamic` | 当前轨迹附近，状态和载荷小扰动怎样满足连续运动方程？ | 完成动态一致初始化后才具有该含义 | 支持已声明可线性化的力律与状态模型 |

例如 `d(toe)/d(wheel_travel)` 与 `d(toe)/dt` 是两个独立输出。`toe_dot / wheel_travel_dot` 只是实际轨迹方向上的比值；多输入运动时不等于控制其他输入后的偏导，轮行程速度为零时也不能使用。

动态仿真中的几何滚心并不要求车身正在侧倾：它来自该构型上的指定虚拟运动。受载滚心则必须声明载荷分配、边界及响应域，不能与几何滚心共用一个未限定的名字。

K/C 属于模型激活配置，Study 属于求解方式，响应域属于测量问题。这三者不互相推断。

## 4. 唯一声明及结果契约

模型中的 `measurements` 声明被测物理量和 frame；求解计划中的 `characteristics` 声明本次请求。统一请求包含：

| 字段 | 含义 |
|---|---|
| `id`、`definition_version` | 稳定请求身份及指标定义版本 |
| `domain` | 上述四类响应语义之一 |
| `samples` | 工况内采样选择；动态只选择已接受且一致的输出状态 |
| `measurements` | 测量 ID，不通过 wheel 名称或数组下标猜测 |
| `perturbations` | 指定坐标运动、frame 点驱动、wrench 或现有输入通道的单位增量 |
| `boundary` | 保持/释放的已声明运动坐标、附加增量固定方向、参考 frame |
| `definition` | 指标类型及必要的分组、轴、载荷权重或截面 |

增量固定车身表示该样本周围 `delta body_pose = 0`，不会把浮动车身改成世界固定实体。释放某个运动边界只能引用已有边界，不能由特性请求改变关节或停用衬套。已存在的零增量运动边界默认保持；释放必须显式声明。

声明样例，仅示意拟议接口，当前尚不可执行：

```json
{
  "characteristics": [
    {
      "id": "front.camber_per_left_travel",
      "definition_version": 1,
      "domain": "kinematic",
      "samples": "all",
      "measurements": ["front.left.camber", "front.right.camber"],
      "perturbations": [{
        "id": "left_travel",
        "kind": "coordinate",
        "coordinate": "rig.left_travel",
        "unit": "m"
      }],
      "boundary": {
        "hold_coordinates": ["rig.right_travel", "steering.rack"],
        "hold_frame": "chassis.reference",
        "reference": "chassis.reference"
      },
      "definition": {"kind": "measurement_derivative"}
    }
  ]
}
```

坐标必须真实存在且能转成一致的约束行；无车身模型可明确使用 `world`。同一声明可以用于台架和整车，所绑定实体及边界不同。不同物理模型的结果不因使用同一 API 就自动等价。

结果沿用原生 named blocks，并增加特性请求清单和响应通道版本。查询拟议为 `result.characteristic(id)`，返回：

- 采样索引、工况身份/时间、测量 ID、扰动 ID 和固定的数组维度。
- 数值与分量单位；导数保留分子/分母单位，六轴矩阵不使用一个笼统单位。
- 响应域、边界指纹、定义版本、frame 与切空间约定。
- 每采样点的有效性、原因、约束/线性响应残量、秩与导数来源。
- 中心/轴等复合指标的基础运动或力矩信息，便于定位不一致。

动态点的身份包括 case ID、sample ID、时间、状态/模式身份；不能只用数组第几个样本。模型和求解计划保持原有指纹，特性请求另有规范化指纹，不为输出选择另造权威物理模型。

结果查询不启动 native 求解、重配平或重新加载建模资源。请求运行时响应而未产生通道时报告缺失；纯代数测量可使用已有状态通道计算。

契约变更必须同时覆盖 `suspension_contracts` 的 solve-plan schema、multibody-case 请求编码、native reader、结果通道 schema 和 capability；编译器不得只保留 Python 对象而在重建 case 时丢掉请求。能力声明包含请求域、扰动类型、定义版本、特性通道版本，以及各有状态力律支持的响应域。所有层拒绝未知字段/版本，不接受 native 静默忽略。沿用文档契约扩展，不为每个指标新增 ABI 函数；是否升级契约版本由实际兼容性决定。

## 5. 模块划分及依赖方向

```text
作者声明 / Case
  -> ResolvedModel + ResolvedSolvePlan.characteristics
  -> compile_resolved：引用/单位/响应域/capability 校验
  -> suspension_kernel_run
       原有 static / dynamic solve
       -> 指定有效样本
       -> 物理线性化 + 请求方向响应
       -> 原有状态通道 + 特性基础通道
  -> RawContractResult / ResultEnvelope
  -> characteristics：测量、导数、中心、轴的纯算子
  -> outputs / vehicle / report
```

建议 Python 落点：

```text
modeling/characteristics.py    请求和边界的纯数据声明
characteristics/
  values.py                   无求解行为的输入/结果值类型
  measurements.py             角度、frame 运动及其导数
  motion.py                   Twist、相对运动、瞬时轴
  centers.py                  中心定义与截面计算
  registry.py                 少量显式 kind/version 分派
results/characteristics.py    原生通道校验、解码和查询适配
```

`characteristics/` 只依赖低层数据与空间代数，不导入 `results`、作者层、Case 或求解器；`results` 向它提供只读基础量。`modeling` 不反向导入 `characteristics/` 的计算逻辑。`outputs`、`vehicle`、`report` 消费统一结果或算子，不各自复制算法。

`results/characteristics.py` 将特性结果适配为具名基础通道供 `outputs/derived.py` 消费；纯代数表达式继续只接收其声明的映射，不能直接读取 `ResultEnvelope` 或发起 native 请求。

Native 建议新增一个职责模块 `mb_linearization`：组装物理工作样本的约束/平衡/连续动态导数，校验响应边界并求请求方向。它依赖 `mb_model`、`mb_joint`、`mb_force`、`mb_linear` 及必要的物理原语，不依赖 `mb_solve_static`、`mb_solve_dynamic`、`mb_output` 或产品包。求解器、输出调度和 ABI 向下调用它，避免循环。

同一力律的标量与方向导数继续归已有 element/tire 模块。提取静态物理切线时，移动共享组装部分到新模块；Newton 的增量参数映射、gauge、pin 和步长系数仍归求解器。不能在新模块再复制一份力律或静态残差算法。

现有模块门的依赖白名单需要在实施中显式更新并附 DAG 证据；不以白名单调整掩盖反向依赖。

## 6. 数学与可辨识性

### 6.1 运动学响应

在当前构型用原生约束雅可比 `J`，叠加请求驱动行 `D` 与保持边界 `H`：

`J` 包含所选真实约束及保持的原运动边界。若请求驱动的是已有运动坐标，替换该边界的增量目标，不能再叠加一条矛盾的零增量行；释放边界按 ID 从响应系统排除，仅影响本次增量问题。下式中的 `D` 只表示尚未包含在 `J` 中的驱动行，所有驱动/保持行在组装前去重并检查相容性。

\[
\begin{bmatrix}J\\D\\H\end{bmatrix}S
=\begin{bmatrix}-\Phi_u\\d\\0\end{bmatrix}.
\]

统一使用有量纲尺度的列/行缩放和秩揭示分解。单位、COM 原点、world/body 增量和旋转左右乘约定在边界明确转换；尺度变换还原后才输出。

驱动后存在零空间时，不能静默把最小范数解当唯一物理运动。对具体测量检查剩余自由运动是否影响它：若 `g_q N = 0`，该测量仍可辨识；否则返回 `unidentifiable`。瞬时轴、接地点轨迹等复合输出需要其所需运动分量可辨识。

柔性连接的完整 C 模型往往没有唯一的纯几何运动。此时增加必要的显式响应边界，或选择平衡/动态响应；不偷偷把衬套替换成理想关节。

### 6.2 平衡响应

令静态物理残差为 `R(x,u)=0`，包含位姿、物理乘子和实际参与的接触/内部变量：

\[
R_x S=-R_u,\qquad y_u=g_x S+g_u.
\]

切线必须包含力律导数和 `d(J^T lambda)` 的几何项。仅有约束雅可比或弹簧材料刚度不构成完整柔度。

在最终收敛态重新评估，不能直接拿上一轮 Newton 分解当最终切线。任意自转角等 gauge 通过显式规约/投影处理；请求能影响被规约方向时必须拒绝该规约，不能从数值置一对角产生虚假刚度。

固定车身与车身自由是不同响应边界。需要凝聚时，在一致坐标和可逆子块条件下实施；不能把自由消元的 Schur 补等同于固定车身。轮胎是否参与沿用真实模型及求解计划，不由指标算子剥离。

### 6.3 轨迹时间导数

\[
\dot y=g_q\dot q+g_v\dot v+g_z\dot z+g_u\dot u+g_t.
\]

位置/角度指标优先由当时的线速度、角速度与参考 frame 运动求导。测量只消费它真实依赖的项。相对车身的指标必须扣除车身平移和旋转，不能仅对世界方向角求导。

### 6.4 连续动态小扰动

对满足原连续方程的轨迹样本 `F(x,xdot,u,t)=0`：

\[
F_{\dot x}\,\delta\dot x+F_x\,\delta x+F_u\,\delta u=0.
\]

这是带约束的动态响应，可能是时变描述符系统。使用一致的状态扰动和约束处理；不能一般性地对质量/描述符矩阵求逆，也不能把位姿/载荷比称为瞬时静态柔度。

首轮动态接口输出请求方向的描述符导数 `F_xdot`、`F_x`、`F_u` 及测量映射，不引入频域或新轨迹积分器。它们定义局部动态系统，并不是当前时刻的唯一位移响应。需要有限时域载荷响应时，应另行定义传播区间和初始扰动，不能只靠当前样本推断。

动态 Newton 矩阵还包含步长、generalized-alpha 参数和前步状态，是离散算法对象。连续响应与离散步导数不共享名称或证据。

部分状态模型带显式步长依赖、return mapping 或未公开连续状态方程，其动态响应能力需逐模型审计；不因已有方向导数而统一宣称支持。

## 7. 侧倾中心、纵倾中心与瞬时轴

所有中心定义要求：参考 frame、参与测量点/实体、驱动方向及保持边界、计算定义版本和输出截面。中心定义不通过前后轴/左右轮名称推断。

| 指标 | 定义要求 | 支持的样本 |
|---|---|---|
| 几何侧倾中心 | 指定接地点、允许悬架运动、横向载荷权重和 YZ 内的等效作用线 | 准静态与动态的当前构型，要求运动及载荷可辨识 |
| 单轮侧视瞬心 | 指定轮端相对参考体的运动及 XZ 截面 | 同上 |
| 几何纵倾中心 | 指定前后作用点/分组、允许悬架运动及纵向载荷权重，再形成 XZ 内的等效作用线 | 同上；不等同于单轮侧视瞬心 |
| 受载响应定义的中心 | 显式载荷权重、车身/轮端边界和静态响应定义 | 合格平衡态；动态版本需要额外时间/响应定义 |
| 空间瞬时螺旋轴 | 指定被测体、参考体和唯一虚拟运动 | 准静态与动态当前构型，要求运动可辨识；纯平移时 Twist 有效而有限轴不可定义 |

单个 Twist 的互易 wrench 通常不唯一。首批几何中心采用下面两种确定定义，不从单个运动直接推断任意六轴力：

- `roll_force_equivalent_v2`：为每个指定接地点声明横向载荷权重 `w_i`，禁止纵向力和纯力偶，令虚拟力 `F_i=(0,w_i,f_zi)`。在声明的全部允许接地点运动列 `V_i` 上求解 `V_i^T F_i=0`。对单一跳动方向，`f_zi=-w_i v_yi/v_zi`。
- `pitch_force_equivalent_v1`：声明纵向载荷权重，禁止横向力和纯力偶，令 `F_i=(w_i,0,f_zi)`，同样满足 `V_i^T F_i=0`；单一跳动方向为 `f_zi=-w_i v_xi/v_zi`。

权重为明确输入，使用固定的单位力归一化；只缩放全部权重不改变中心，改变载荷分配则可能改变中心。每个 `f_zi` 必须唯一且满足全部虚功方程。存在不相容运动列或不可辨识竖向分量时报告原因，不静默取最小二乘近似。`V_i` 由真实约束及保持边界的完整允许运动基映射到接地点；提取该基时不把用于量测的单位驱动当作零增量锁定。可辨识性要求覆盖全部允许运动，不只核对所选那一列。

在同一参考 frame 下按完整接地点位置 `r_i` 求 `F=sum(F_i)`、`M=sum(r_i x F_i)`。侧倾等效线在声明的 YZ 投影中满足 `M_x=y F_z-z F_y`，在明确的 `y=y_ref` 处报告高度 `z=(y_ref F_z-M_x)/F_y`；`x_section` 仅为该二维定义的显示截面。纵倾等效线在 XZ 投影中满足 `M_y=z F_x-x F_z`，在明确的 `x=x_ref` 处报告高度 `z=(M_y+x_ref F_z)/F_x`；`y_section` 同样显式指定。总横向/纵向力为零时相应中心不可定义。

这是声明载荷分配下的投影等效中心，不宣称是任意载荷共享的唯一三维点。接口同时返回作用线、分配权重与合力/合力矩。作用点力臂不假设接地点在 `z=0`；不同路面高度、空间安装角及多轴组合由声明数据表达。

更一般的空间指标若用合 wrench `F,M` 构造作用线，先检查 `F` 非零，分离平行于力的自由力矩，再由 `r0 = (F x M) / |F|^2` 表示等效作用线。存在不能消掉的自由力矩时，不能把它丢弃后声称得到了唯一纯力中心；具体指标定义应拒绝或明确输出作用线与剩余力偶。作用线平行且不在所选截面内时没有交点；作用线位于截面内时交点不唯一。两者分别报告原因。

现有 `ResultEnvelope` 的滚心定义以 `roll_center_legacy_v1` 逐项迁移，保留原数值、最小二乘选择行为和符号，不宣称它具备新的可辨识性保证。新定义加入接地点高度项、显式载荷分配和可辨识性检查。两者在声明、版本和结果元数据中区分；旧测量维持原定义，新请求显式选择新定义。

## 8. 运行时提取与性能

动态原生 `State` 包含轮胎松弛、接触质量、转滑、Maxwell 等内部状态及步长，而现有结果通道没有无损保存全部工作样本。因此涉及力律/动态状态的响应在 native 已接受状态上按需计算；无需先建设完整检查点系统。

- 静态样本：平衡审计合格后提取。
- 动态样本：输出时刻的真实一致状态提取；只读核实接受步中 return mapping 后的状态、物理乘子和活动模式是否同步。若恢复一致性需要更新内部状态、重新执行 return mapping 或提交新状态，该响应样本不可用，并返回原因。如输出经过插值，须由原仿真的采样机制提供完整一致状态；特性计算不自行恢复或修正它，不能仅对插值位姿线性化。
- 只读借用状态、输入、物理乘子和活动模式；采样计算不提交状态、执行新的 return mapping 或改变后续积分。
- 同样本、同域、同边界、同活动模式共享矩阵/分解；不同域或不同释放边界不能复用同一个结果。
- 分解复用需明确 factorization/solve-many 接口；现有一次性 `solve_linear` 不代表已缓存分解。
- 默认输出请求方向的响应和诊断，完整稠密矩阵仅作为显式诊断选项。
- 无特性请求时不增加切线计算或额外输出块；开启后单独测量时间、分解次数和结果体积。

## 9. 有效性与失败语义

编译阶段拒绝未知实体、单位错误、不支持的请求域/力律和矛盾边界。合法请求在个别样本无法定义时，以每样本状态报告，不中断原本成功的仿真。

状态包括 `valid`、`unidentifiable`、`singular`、`nonsmooth`、`not_equilibrium`、`undefined_geometry`；缺失输出通道是查询错误。无效数值使用固定形状的缺失值及原因，不能用零或截断到 ±1000 m 伪装。

在接触进入/退出、限位切换、曲线不可微点或 return mapping 边界，不提供未经说明的双侧导数。首轮报告 `nonsmooth`；单侧导数若后续支持，须记录方向和活动分支。已有受控数值导数回退可保留，但必须在结果中标明来源与步长，不能标为解析。

物理 gauge 与真实机构秩亏分别报告；病态但可解的响应同时给残量和尺度后的条件诊断。一次采样失败不能通过缓存上一点结果掩盖。
