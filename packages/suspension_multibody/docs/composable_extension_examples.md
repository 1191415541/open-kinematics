# Extending the composable model

Three worked examples, and each one is **executed** by
`scripts/check_composable_release.py`.  That is the point of this file: an
example that is only read drifts, and an example that is run cannot.

Every fenced block marked `python runnable` is self-contained: it carries its own
imports, keeps no state another block needs, and runs in a fresh interpreter.
The probe extracts each block, writes it to a file, and runs it with the
repository on `sys.path`; a block that raises fails the release check.

The examples answer the three questions the architecture is supposed to make
cheap:

| Example | Question it answers |
|---|---|
| E-1 | How do I add a subsystem template and get entities out of it? |
| E-2 | How do I add a rig and run a topology through it? |
| E-3 | How does a hardpoint change reach the solve? |

The extension rule is unchanged by all three: a new combination of **existing**
physical elements is a template, a registration, parameters and a test.  A new
*physical law* is not — that still needs the contract and the kernel, and this
file does not claim otherwise.

## E-1 — a new subsystem template

A template is declared as data, or generated by a registered builder, and both
routes end in the same `ModelFragment`.  The builder route is the one that
matters for a new topology: its part count is not fixed, so a template can be
written once and instantiated with however many links the model has.

The role contract is what keeps a template honest.  `get_role(...)` reports the
mounts and property slots the role requires, and `register(...)` refuses a
template that does not declare them — so the example satisfies the role by
construction instead of by copying a list that would silently go stale.

```python runnable
"""E-1: declare a template with a builder and instantiate it into a fragment."""

from suspension_multibody.modeling.instance import ModelFragment
from suspension_multibody.templates.builders import build_fragment, register_builder
from suspension_multibody.templates.model import (
    ConnectionDefinition,
    PartDefinition,
    PropertySlot,
    Template,
)
from suspension_multibody.templates.registry import get, register
from suspension_multibody.templates.roles import get_role


def trailing_arm_builder(parameters, properties, mode, bound_ports) -> ModelFragment:
    """Emit one arm and one pivot per arm, for as many arms as asked for.

    This is what a *builder* buys over a declaration: the part count is a
    parameter, so the same template covers a one-arm and a three-link topology.
    """
    del properties, mode, bound_ports
    arms = int(parameters.get("arms", 2))
    return ModelFragment(
        bodies={
            f"arm_{index}": {"name": f"arm_{index}", "fixed": False}
            for index in range(arms)
        },
        joints={
            f"pivot_{index}": {"kind": "revolute", "body": f"arm_{index}"}
            for index in range(arms)
        },
    )


register_builder("trailing_arm_builder", trailing_arm_builder)

# The role says what a suspension subsystem must offer; satisfying it from the
# role's own report is what keeps this template valid as the role evolves.
role = get_role("suspension")
template = Template(
    name="torsion_beam_axle",
    role="suspension",
    parts=(PartDefinition("arm_0"),),
    connections=tuple(
        ConnectionDefinition(mount, mount, joint="revolute")
        for mount in role.required_mounts
    ),
    property_slots=tuple(
        PropertySlot(name, "-", default=0.0) for name in role.required_slots
    ),
    builder="trailing_arm_builder",
)
register(template)

fragment = build_fragment(
    get("torsion_beam_axle"),
    mode="K",
    properties={},
    instance=("axle",),
    parameters={"arms": 3},
)

assert isinstance(fragment, ModelFragment)
assert sorted(fragment.bodies) == ["arm_0", "arm_1", "arm_2"]
assert sorted(fragment.joints) == ["pivot_0", "pivot_1", "pivot_2"]
assert fragment.provenance is not None
assert fragment.provenance.template == "torsion_beam_axle"
print("E-1 ok:", sorted(fragment.bodies))
```

Note what the fragment does **not** contain: no residual, no Jacobian, no
solver.  A fragment is entities and provenance.  Solving is the kernel's, and
`A5` traces an entity back to its template through exactly that provenance.

## E-2 — a new rig, on a topology it has never seen

A rig is a `RigSpec`: what it drives, which study reads the model, and what it
measures.  Its `family` is the contract routing key, deliberately separate from
the bench's name — so a bench called `roll_bench` runs the `kc_quasi_static`
reading without having to be called after it.

Registering a bench is a declaration in two registries and no code change
anywhere else.  The plan states the routing, the compiler produces the documents
from the model, and the run goes to the native kernel.

```python runnable
"""E-2: register a bench and drive an existing topology through it, for real."""

from dataclasses import replace

from suspension_contracts import pack_container

from suspension_multibody.compilation import KcStudyInputs, compile_plan, plan_for
from suspension_multibody.preparation.assembly import build_front_axle
from suspension_multibody.rigs.compose import _RIG_ASSEMBLIES
from suspension_multibody.rigs.rig import RIGS
from suspension_multibody.schema import FrontAxleModel, MassSpec
from suspension_multibody.simulation import run_compiled
from suspension_multibody.simulation.request import (
    CompiledSimulation,
    SimulationRequest,
)

model = FrontAxleModel(
    hardpoints={
        "uca_front": [-100, -500, 400],
        "uca_rear": [100, -500, 400],
        "uca_outer": [0, -700, 450],
        "lca_front": [-120, -500, 150],
        "lca_rear": [120, -500, 150],
        "lca_outer": [0, -700, 150],
        "tierod_inner": [100, -400, 250],
        "tierod_outer": [50, -700, 250],
        "wheel_center": [0, -700, 300],
        "rack_center": [0, 0, 250],
    },
    mass=MassSpec(sprung_mass=1000),
)

# 1. The bench: same driving as the K&C bench, a different name, its own output.
RIGS["roll_bench"] = replace(
    RIGS["kc_quasi_static"],
    name="roll_bench",
    family="kc_quasi_static",
    outputs=("wheel_load", "roll_angle"),
)
# 2. Which kind of assembly it may be attached to.  Also a registration.
_RIG_ASSEMBLIES["roll_bench"] = "axle"

try:
    plan = plan_for(
        "roll_bench",
        mode="K",
        inputs=KcStudyInputs(
            name="extension-example",
            wheel_values_mm=(0.0, 20.0),
            rack_values_mm=(0.0,),
        ),
    )
    # The bench answers the family and the study; the caller named neither.
    assert plan.rig == "roll_bench"
    assert plan.family == "kc_quasi_static"
    assert plan.study == "quasi_static"

    assembly = build_front_axle(model, "K")
    model_document, case_document, model_blob, case_blob, metadata = compile_plan(
        plan, assembly
    )
    assert metadata["rig"] == "roll_bench"
    assert metadata["family"] == "kc_quasi_static"

    run = run_compiled(
        CompiledSimulation(
            request=SimulationRequest(
                assembly="axle",
                rig="roll_bench",
                family=plan.family,
                study=plan.study,
                model=assembly,
                case=case_document,
                name="extension-example",
            ),
            model_document=model_document,
            case_document=case_document,
            model_payload=model_blob or pack_container(model_document),
            case_payload=case_blob or pack_container(case_document),
            metadata=metadata,
        )
    )

    # A real solve, not a status flag: the wheel actually travelled.
    assert run.status == "success", run.raw.failure_evidence
    assert len(run.raw.cases) == 2
    states = run.raw.states
    assert states.shape[0] == sum(int(case["sample_count"]) for case in run.raw.cases)
    print("E-2 ok:", run.status, len(run.raw.cases), "cases on rig", plan.rig)
finally:
    del RIGS["roll_bench"]
    del _RIG_ASSEMBLIES["roll_bench"]
```

Two things this example deliberately does **not** claim.  The bench's own
contributed bodies (`wheel_carrier_L`/`_R`, `bench_frame`) are what a bench
*declares*; the compiled document is authored from the assembly, so the run
proves the bench routes and drives, not that its furniture is in that document.
`tests/composable/test_extension_proof.py` holds the other half.

## E-3 — a hardpoint change reaching the solve

A hardpoint is data, and the model is rebuilt from it.  Nothing in the bench, the
compiler or the kernel is edited to move it: the derived geometry follows, and the
solved response changes.  This is what "the interface adapts to the hardpoints"
means concretely — the numbers below are the check.

```python runnable
"""E-3: move a hardpoint and show the change reaching the solved response."""

from suspension_multibody import api
from suspension_multibody.preparation.assembly import build_front_axle
from suspension_multibody.schema import (
    CaseSpec,
    DisplacementControl,
    FrontAxleModel,
    MassSpec,
)

HARDPOINTS = {
    "uca_front": [-100, -500, 400],
    "uca_rear": [100, -500, 400],
    "uca_outer": [0, -700, 450],
    "lca_front": [-120, -500, 150],
    "lca_rear": [120, -500, 150],
    "lca_outer": [0, -700, 150],
    "tierod_inner": [100, -400, 250],
    "tierod_outer": [50, -700, 250],
    "wheel_center": [0, -700, 300],
    "rack_center": [0, 0, 250],
}


def sweep(hardpoints):
    """Return the converged states of a K sweep, one per wheel travel."""
    model = FrontAxleModel(
        hardpoints=dict(hardpoints), mass=MassSpec(sprung_mass=1000)
    )
    case = CaseSpec(
        mode="K",
        controls=(
            DisplacementControl(target="wheel_travel_left", values=(0.0, 20.0, 40.0)),
        ),
    )
    return api.run_case(model, case).states


# The assembly carries the point the hardpoint names; moving the hardpoint moves
# the attachment, and the build is otherwise untouched.
moved = dict(HARDPOINTS)
moved["uca_outer"] = [0.0, -700.0, 470.0]

before = build_front_axle(
    FrontAxleModel(hardpoints=dict(HARDPOINTS), mass=MassSpec(sprung_mass=1000)), "K"
)
after = build_front_axle(
    FrontAxleModel(hardpoints=dict(moved), mass=MassSpec(sprung_mass=1000)), "K"
)
attached_before = before.points[("upright_L", "upper_arm_L_outer")]
attached_after = after.points[("upright_L", "upper_arm_L_outer")]
assert attached_before[2] == 450.0
assert attached_after[2] == 470.0

base = sweep(HARDPOINTS)
shifted = sweep(moved)
assert [state.drives["wheel_travel_left"] for state in base] == [0.0, 20.0, 40.0]

# The driven coordinate is prescribed, so the travel itself is unchanged and the
# *derived* response is where the moved hardpoint shows up: a 20 mm higher upper
# outboard point gains camber over the same travel.
camber_base = [state.metrics["left_camber_deg"] for state in base]
camber_shifted = [state.metrics["left_camber_deg"] for state in shifted]
assert camber_base[0] == shifted[0].metrics["left_camber_deg"] == 0.0
assert camber_shifted[1] < camber_base[1]
assert camber_shifted[2] < camber_base[2]
print("E-3 ok: camber", [round(v, 4) for v in camber_base], "->",
      [round(v, 4) for v in camber_shifted])
```

The perturbation is 20 mm and the response is ~0.31° of camber at 20 mm of
travel: a change larger than float noise by three orders of magnitude, and in the
direction the geometry implies.  A hardpoint that reached the model but not the
solve would leave the camber exactly where it was.

## Where the rest of the extension story lives

| Concern | Home |
|---|---|
| the bench's own contributed entities, and capability branching | `src/suspension_multibody/rigs/bench.py` |
| port matching, ambiguity refusal, adaptive mounting geometry | `src/suspension_multibody/connections/` |
| the global single-axle/vehicle rules | `src/suspension_multibody/connections/policy.py` |
| subsystem composition into one SI assembly | `src/suspension_multibody/subsystems/si_assembly.py` |
| what a run is, what a model is, and the documents they imply | `src/suspension_multibody/compilation/` |
| result decoding and derived outputs | `src/suspension_multibody/results/`, `outputs/` |
| the executed extension proof (new topology, new bench, perturbations) | `tests/composable/test_extension_proof.py` |

`tests/composable/` is the stronger statement of the same claims: it adds a
`synthetic` trailing-arm axle whose connection graph is unlike the built-in double
wishbone, and a synthetic physical loading bench, and runs both through the
production entry.  The fixtures are marked `_synthetic: true` in the data and
`SYNTHETIC FIXTURE` in their headers, and they prove architecture and solve
paths only — they are not engineering models and nothing here claims accuracy.
